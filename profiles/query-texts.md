# Профиль: тексты запросов

Этот файл — project-specific profile для оформления `Запрос.Текст`.

## Когда применять профиль

- если inventory-pass подтвердил `has_query_text`;
- если меняется `Запрос.Текст`;
- если внутри метода есть SQL-like литерал запроса;
- если нужно решить, выносить ли текст запроса в helper.

## Канонический контракт

- В изменяемом коде `Запрос.Текст` по умолчанию задается через отдельный
  helper, а не inline-литералом внутри основного метода.
- Helper текстов запросов живут в отдельной области `#Область ТекстыЗапросов`
  внутри служебного слоя модуля.
- Имя helper-а должно отражать роль запроса и быть согласовано с общим
  паттерном именования внутри модуля.
- Исторические префиксы вроде `РХ_` в имени query-helper-а не нужны, если это
  не внешний контракт.
- Сам helper оформляется как обычная функция: `ВозвращаемоеЗначение`,
  структурированный текст, финальный `Возврат`.
- Строковый литерал helper-а начинается на строке присваивания:
  `ВозвращаемоеЗначение = "`.
- Следующие строки текста запроса сразу идут в форме `|...`; не добавляйте
  промежуточную пустую строку, отдельную строку только с кавычкой или лишний
  визуальный сдвиг перед телом литерала.
- Структурные отступы внутри текста запроса после `|` пишутся табами, а не
  пробелами: `|<TAB>Поле`, `|<TAB>И Условие`.

## Предпочтительная форма вызывающего метода

1. `Запрос = Новый Запрос();`
2. `Запрос.Текст = <QueryTextHelper>();`
3. `Запрос.УстановитьПараметр(...);`
4. `Результат = Запрос.Выполнить();`
5. `Выборка = Результат.Выбрать();`

Это правило нужно не ради ритуала. Оно:

- убирает шум текста запроса из основного сценария метода;
- делает форму соседних методов повторяемой;
- дает стабильную точку для review и сравнения запросов;
- упрощает навигацию по модулю.

## Что считать нормой

- отдельная область `ТекстыЗапросов`;
- один helper на один смысловой запрос;
- в основном методе виден только вызов helper-а, а не тело запроса;
- имя helper-а отражает роль запроса и согласовано с соседними query-helper-ами.

## Что считать style-ошибкой

- `Запрос.Текст = "..."` прямо внутри основного метода без явной причины;
- длинный запрос размазан по телу метода и ломает чтение сценария;
- helper текста запроса назван случайно или с ненужным legacy-префиксом;
- helper текста запроса живет вперемешку с обычной orchestration-логикой без
  отдельной области;
- один и тот же метод смешивает query-helper и inline query text без причины;
- литерал helper-а начинается не на строке `ВозвращаемоеЗначение = "`;
- тело литерала query-helper-а получило лишний визуальный сдвиг или пустую
  строку между присваиванием и первой строкой `|...`;
- внутри query text после `|` использованы пробелы для структурного отступа
  вместо табов.

## Допустимые исключения

- очень короткий и одноразовый запрос можно оставить inline только если вынос в
  helper заметно не улучшает чтение;
- такое исключение должно быть осознанным и редким, а не default-паттерном.
