# Жёсткие блокеры перед завершением

Если нарушен любой пункт из разделов ниже, задача не считается
завершённой.

`FAIL` допустим только как явный residual finding или риск. `UNRUN` недопустим
для обязательной и применимой проверки вообще.

## Покрытие

- Режим (`consultation`, `real-code` или `skill-audit`) определен до review.
- Scope-флаги зафиксированы до выбора pack-ов.
- Coverage-plan материализован из `checks.jsonc`, а не выбран ad hoc по памяти.
- Каждый обязательный и применимый check переведен в terminal status:
  `PASS`, `FIXED`, `FAIL` или `N/A`.
- Ни один mandatory+applicable check не оставлен в `UNRUN`.
- Каждый `N/A` снабжен явной причиной.
- `examples/few-shots.md` не использовался как замена rules/process-pack-ам.
- Для `skill-audit` проверена согласованность `SKILL.md`, `agents/openai.yaml`,
  `checks.jsonc` и process-layer.

## Порядок выполнения

- Если scope включал real-code и запись была допустима, локальные
  детерминированные findings не оставлены сырым списком, а исправлены.
- После правок выполнен rerun затронутых checks.
- `FIXED` используется только там, где rerun реально был выполнен.
- Пользователю вынесены только residual `FAIL`, риски или осознанно нечиненые
  решения, а не то, что агент мог безопасно исправить сам.

## Структура и модульный уровень

- Если scope включал реальный `*.bsl`-модуль целиком, верхний уровень файла был
  проверен до анализа методов.
- В каждом новом или измененном реальном `*.bsl`-модуле есть завершенная
  шапка по `references/module-header.md`.

## Безопасность поведения

- `references/behavior-change-guard.md` применен ко всем реальным edit-pass-ам.
- Не изменены защитные условия, fallback-порядок, момент создания объекта,
  источник даты, вызываемый API или условия исключения без отдельного
  обоснования.
- Legacy/external-contract boundary проверен до упрощения адаптационного кода.
- При конфликте между style-cleanup и безопасностью побеждает безопасность.

## Верификация

- `process/verify-recipes.md` выполнен по каждому измененному файлу или честно
  задокументирован fallback.
- Для query-text и BSL-formatting повторно закрыты соответствующие checks после
  верификации.
- Для BSL-whitespace scope выполнен `scripts/check_bsl_blank_line_tab_rhythm.py`
  или явно зафиксировано, почему машинный guard неприменим.
- Diff проверен на лишние изменения вне intended scope.

## Отчет наружу

- Финальный ответ содержит coverage-summary по статусам.
- Отдельно перечислены auto-fix-ы.
- Отдельно перечислены residual `FAIL`/риски, если они есть.
- Если verify был ограничен средой, это явно сказано, без имитации полной
  проверки.
