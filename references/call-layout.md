# Layout вызовов и сигнатур

Этот файл решает только форму записи вызовов, сигнатур и выражений. Он не
решает, какой API вызывать.

## Правило

Держите вызов в одну строку, если он помещается в рабочую ширину, читается как
один атомарный шаг и аргументы не несут отдельных стадий алгоритма.

Раскрывайте многострочно, если:

- строка становится слишком длинной или плохо сканируется;
- аргументы сами являются стадиями или вычисляются отдельно;
- есть вложенный вызов, условное выражение или длинный литерал;
- нужно видеть каждый аргумент при review.

## Сигнатуры

- Короткую сигнатуру процедуры/функции оставляйте в одну строку.
- Длинную сигнатуру раскрывайте вертикально, если она хуже читается или
  выходит за рабочую ширину.
- Не раскрывайте сигнатуру механически только потому, что параметров несколько.

## Вызовы

Менее удачно:

```bsl
РезультатПоиска = БУС_ОбщегоНазначенияВызовСервера.ПолучитьЗначениеПоИдБУСОбъекта(
	Сайт,
	ТипОбъекта,
	ИдДокумента
);
```

Лучше, если строка помещается и вызов атомарный:

```bsl
РезультатПоиска = БУС_ОбщегоНазначенияВызовСервера.ПолучитьЗначениеПоИдБУСОбъекта(Сайт, ТипОбъекта, ИдДокумента);
```

Многострочная форма лучше, когда аргументы длинные или имеют самостоятельный
смысл:

```bsl
ТекстОшибки = СтрШаблон("Ошибка при создании документа %1 (Ид: %2): %3",
	ИмяДокумента,
	ДокументXML.Ид,
	ИнфоОшибки.Описание
);
```

Не превращайте layout-правку в изменение порядка вычислений или замену API.
